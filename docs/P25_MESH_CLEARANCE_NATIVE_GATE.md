## Real new verification — triangulated geometry, not merely point-cloud distance

A standalone NumPy/SciPy script reconstructs the authored Catmull–Rom surfaces and generates *actual triangle faces* at controllable per-control-cell subdivision. It calculates triangle-to-triangle distances using vertex/face, edge/edge and segment/face intersection tests; a conservative sphere-bound KD-tree candidate phase accelerates the computation. It is NOT the original B3.8 runtime tessellation or ball collision implementation.

At **four subdivisions per control cell**, independently tested against **all 31 non-road architectural surfaces**:

| Original physical stage | Closest reconstructed road/architecture triangle distance |
|---|---:|
| P23 original | **0.000m**, model intersection detected |
| P24 option A | **11.180m** |
| P24 option B (documented in separate public Draft PR #25) | **11.092m** |
| P24 option C | **15.551m** |
| P25 selected C | **15.551m** |

Reconstructed selected-P25 3 / 4 / 6 subdivisions yield **15.551739 / 15.551491 / 15.551383m** respectively. The 5 separate synthetic geometry algorithm tests pass. **Never read these as guarantees that the native B3.8 ball, full renderer tessellation, collision thickness or camera will be clear.** The zero-distance original is a reconstructed model intersection, not a witnessed game collision.
